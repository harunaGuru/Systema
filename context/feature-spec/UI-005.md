# UI-005 — Editor Home Screen (Mock)

## A. Identity and Objective

- **Feature ID:** UI-005
- **Title:** Editor Home Screen (Mock)
- **Primary objective:** Build the `/editor` home screen that reuses the existing editor chrome and presents a centered call-to-action. No backend, no persistence, no dialogs yet.
- **Expected outcome:** Navigating to `/editor` shows the navbar, the floating left sidebar (toggleable), and a centered heading, description, and New Project button. Clicking the button is a no-op in this unit; wiring to the Create dialog is UI-006.
- **References:** `planning/feature-map.md` UI-005; `context/ui-context.md` Layout Patterns; `context/code-standards.md` Next.js; `AGENTS.md`.

## B. Execution Contract

The agent must do all of the following without asking the user for confirmation, in this order:

1. Read `AGENTS.md`, `context/ui-context.md` (Layout Patterns), `context/code-standards.md` (Next.js).
2. Confirm UI-004 is in place: `components/editor/editor-shell.tsx`, `editor-navbar.tsx`, and `project-sidebar.tsx` exist, and `lucide-react` is installed.
3. Create `app/editor/page.tsx` per D.1.
4. Modify `components/editor/editor-shell.tsx` per D.2 so the canvas placeholder is replaced by a `children` slot, and `app/page.tsx` renders the editor home instead of the shell placeholder.
5. Replace `app/page.tsx` per D.3.
6. Run the **Checks** block in Section I top to bottom.
7. Fix any in-scope failure and re-run the failing check.
8. Report PASS or FAIL per Section J. On PASS, state the agent has stopped and is awaiting the next feature. On FAIL, state the exact blocker and stop.

Do not install any package. Do not modify `app/globals.css`, `components/ui/*`, or `context/*`.

## C. Context and Dependencies

- **Prerequisites:** UI-004 complete and verified.
- **Contract consumed:** `EditorShell` from UI-004. This unit extends it to accept `children` so the home screen and later the editor route can supply their own center content.
- **Approved decisions:** The editor home screen is described in `ui-context.md` under "Homepage" and the feature map's UI-005 entry. The centered content is a heading, a description, and a New Project button with a `Plus` icon. Do not wrap the content in cards.
- **No API calls, no mock project data in this unit.** The sidebar's empty states remain as UI-004 left them.

## D. Implementation Requirements

### 1. `app/editor/page.tsx`

A Server Component (no `"use client"` needed). It renders `<EditorShell>` and, inside it, the home content.

Structure:

- Imports `EditorShell` from `@/components/editor/editor-shell` and `Plus` from `lucide-react`.
- Returns `<EditorShell>` containing a centered block:
  - Outer wrapper: `flex flex-col items-center justify-center h-full gap-6 px-6 text-center`.
  - `<h1>` with `text-2xl font-medium text-text-primary` and text "Create a project or open an existing one".
  - `<p>` with `text-sm text-text-muted max-w-md` and text "Start a new architecture workspace, or choose a project from the sidebar."
  - A shadcn `<Button>` with `Plus` icon (`h-4 w-4 mr-2`) and text "New Project". `onClick` is not wired in this unit; render it as a plain `<Button>` without a handler, or with an empty `onClick` that does nothing. Do not add a dialog.
- No `use client`, no state, no hooks. The button being a no-op is intentional.

If `EditorShell` currently does not accept `children`, complete D.2 first, then return to this step.

### 2. Update `components/editor/editor-shell.tsx`

The shell must accept `children` and render them in place of the hardcoded "Canvas placeholder" div.

Changes:

- Add `children?: React.ReactNode` to the component props.
- In the `<main>` element, replace the current placeholder `<div>` with `{children}`. Keep the `<main>` wrapper, its `pt-14 min-h-screen bg-bg-canvas` classes, and the `h-[calc(100vh-3.5rem)]` constraint on a wrapper inside `<main>` so the children fill the available height.
- Do not change the navbar or sidebar props or behavior. Do not change `useState`.

No other changes to `editor-shell.tsx`.

### 3. `app/page.tsx`

Replace with a page that renders the editor home so `/` shows the same screen as `/editor` in this unit. This avoids a second placeholder and matches the feature map's intent that the home screen is the app's landing view for now. Auth routing (AUTH-001) will later redirect `/` appropriately.

Structure:

- Imports `EditorShell` from `@/components/editor/editor-shell` and `Plus` from `lucide-react`.
- Renders the same centered block as D.1, or, to avoid duplication, re-exports the editor page component by importing it. Prefer the duplication-free approach: import the component from `./editor/page` and render it. If that import path causes issues with Next.js conventions, duplicate the JSX from D.1 instead and note the duplication in the report.

Do not add metadata changes.
