# UI-006 — Project Dialogs (Mock)

## A. Identity and Objective

- **Feature ID:** UI-006
- **Title:** Project Dialogs (Mock)
- **Primary objective:** Build the Create, Rename, and Delete project dialogs with local state and slug preview, wire them to the sidebar actions and the home screen button, and manage their state through a dedicated hook. No API calls, no persistence.
- **Expected outcome:** The New Project button (in the sidebar and on the home screen) opens the Create dialog with a name input and a live slug preview. Owned project items show rename and delete actions that open their respective dialogs. All three dialogs close on cancel and perform a mock action on confirm.
- **References:** `planning/feature-map.md` UI-006; `context/ui-context.md` Layout Patterns, Interaction States; `context/code-standards.md` Styling, Next.js; `AGENTS.md`.

## D. Implementation Requirements

### 1. `hooks/use-project-dialogs.ts`

A client hook (`"use client"` is not needed at the top of a hook file, but the file is only imported by client components).

Return shape:

- `activeDialog`: `"create" | "rename" | "delete" | null`
- `targetProject`: `{ id: string; name: string; isOwner: boolean } | null`
- `openCreate(): void`
- `openRename(project: { id: string; name: string; isOwner: boolean }): void`
- `openDelete(project: { id: string; name: string; isOwner: boolean }): void`
- `close(): void`

Behavior:

- `openCreate` sets `activeDialog` to `"create"` and clears `targetProject`.
- `openRename` and `openDelete` set `activeDialog` and `targetProject` accordingly.
- `close` sets both to `null`.
- No API calls, no async, no loading state in this unit. A `loading` field is not required; add it only in the spec that wires real actions.

### 2. `components/editor/dialogs/create-project-dialog.tsx`

A client component. Props:

- `open: boolean`
- `onOpenChange: (open: boolean) => void`
- `onSubmit: (name: string) => void`

Structure:

- shadcn `<Dialog open={open} onOpenChange={onOpenChange}>`.
- Title "Create project".
- Description "Give your project a name. A slug will be generated automatically."
- A shadcn `<Input>` for the project name, controlled by local `useState`, `autoFocus`.
- Below the input, show the live slug: a `<p>` with `text-xs text-text-muted` reading `Slug: <slug>` where `<slug>` is derived from the name by lowercasing, replacing runs of non-alphanumeric characters with a single hyphen, and trimming leading/trailing hyphens. If the name is empty, show `Slug: —`.
- Footer with a `<Button variant="ghost">` "Cancel" calling `onOpenChange(false)`, and a `<Button>` "Create" disabled when the trimmed name is empty, calling `onSubmit(name.trim())` then `onOpenChange(false)`.
- Submit on Enter inside the input triggers the same Create action when the name is non-empty.

Do not call any action. `onSubmit` is provided by the caller and, in this unit, logs to the console and closes the dialog.

### 3. `components/editor/dialogs/rename-project-dialog.tsx`

A client component. Props:

- `open: boolean`
- `onOpenChange: (open: boolean) => void`
- `currentName: string`
- `onSubmit: (name: string) => void`

Structure:

- Title "Rename project".
- Description including the current name: `Currently named "<currentName>".`
- A shadcn `<Input>` prefilled with `currentName` via `useState` seeded from the prop, `autoFocus`, `onKeyDown` Enter submits.
- Footer with Cancel and a `<Button>` "Save" disabled when the trimmed name is empty or unchanged.
- `onSubmit(name.trim())` then `onOpenChange(false)`.

### 4. `components/editor/dialogs/delete-project-dialog.tsx`

A client component. Props:

- `open: boolean`
- `onOpenChange: (open: boolean) => void`
- `projectName: string`
- `onConfirm: () => void`

Structure:

- Title "Delete project".
- Description: `This will permanently delete "<projectName>". This action cannot be undone.`
- No input.
- Footer with Cancel and a `<Button variant="destructive">` "Delete" calling `onConfirm()` then `onOpenChange(false)`.

### 5. Update `components/editor/project-sidebar.tsx`

Add optional props:

- `projects?: Array<{ id: string; name: string; isOwner: boolean }>` default `[]`
- `onRename?: (project: { id: string; name: string; isOwner: boolean }) => void`
- `onDelete?: (project: { id: string; name: string; isOwner: boolean }) => void`

When `projects` is non-empty, render each project as a list item under the correct tab:

- "My Projects" tab lists projects where `isOwner === true`.
- "Shared" tab lists projects where `isOwner === false`.
- Each item shows the project name in `text-sm text-text-primary` and, when `isOwner`, two icon buttons: `Pencil` calling `onRename?.(project)` and `Trash2` calling `onDelete?.(project)`. Both have `aria-label` and `title`. Icons are `h-3.5 w-3.5`.
- Non-owned items show no action buttons.
- When `projects` is empty or the filtered list is empty, keep the existing "No projects yet." empty state.

Keep the existing New Project button. It must call a new optional prop `onCreate?: () => void` in addition to its current behavior. Do not remove the existing sidebar props (`isOpen`, `onClose`).

### 6. Update `components/editor/editor-shell.tsx`

- Import `useProjectDialogs` from `@/hooks/use-project-dialogs`.
- Import the three dialog components.
- Call the hook.
- Provide a mock project list constant in this file (a small array of 3 items: two owned, one shared) and pass it to `ProjectSidebar` as `projects`.
- Pass `onCreate={dialogs.openCreate}`, `onRename={dialogs.openRename}`, `onDelete={dialogs.openDelete}` to `ProjectSidebar`.
- Render the three dialogs inside the shell, using `dialogs.activeDialog` and `dialogs.targetProject` to drive their `open` and data props. On submit, log to the console and call `dialogs.close()`. On confirm for delete, log and call `dialogs.close()`.
- Do not change the `EditorNavbar` behavior or props. Do not change the `children` slot behavior from UI-005.

### 7. Update `app/editor/page.tsx` and `app/page.tsx`

The home screen New Project button must open the Create dialog. Because the dialog state lives in `EditorShell`, expose an optional `onCreate?: () => void` prop on `EditorShell`, pass it from the home content, and have `EditorShell` call `dialogs.openCreate` when the prop is invoked.

Specifically:

- Add `onCreate?: () => void` to `EditorShell` props. In `EditorShell`, the effective create handler is `onCreate ?? dialogs.openCreate`. Pass that to `ProjectSidebar.onCreate`. Also call `dialogs.openCreate` from the home content button via the `onCreate` prop. The simplest wiring is: `EditorShell` always renders the dialogs and passes `dialogs.openCreate` as the default; the home content calls a prop it receives.
- To avoid prop drilling through the page, give `EditorShell` an optional `homeAction?: React.ReactNode` slot is not required. Instead, the home content's New Project button can call a callback passed down via a new optional prop `onHomeCreate?: () => void` on `EditorShell`, which defaults to `dialogs.openCreate`. The home page passes nothing and relies on the default.

If this wiring becomes confusing, use the simpler approach: keep a single `onCreate` prop on `EditorShell` defaulting to `dialogs.openCreate`, pass it to `ProjectSidebar.onCreate`, and render the home content as a child that receives `onCreate` through a render prop or context. Do not introduce a global state library. Prefer the smallest wiring that satisfies the acceptance criteria.
