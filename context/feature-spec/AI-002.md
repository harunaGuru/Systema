# AI-002 — Graph Generation Task

## A. Identity and Objective

- **Feature ID:** AI-002
- **Title:** Graph Generation Task
- **Primary objective:** Create a Trigger.dev background task that accepts a plain-English prompt and the current canvas state, calls an AI provider (Gemini primary, Groq fallback), and returns a structured JSON graph (nodes and edges) that the client can apply to the canvas.
- **Expected outcome:** The task validates its payload, calls Gemini, falls back to Groq on failure, validates the AI response against the `SystemaNodeData` schema, and writes the generated graph to Postgres/Vercel Blob (or returns it directly). The task runs successfully in the Trigger.dev dashboard.
- **References:** `planning/feature-map.md` AI-002; `context/architecture.md` Stack (AI, Background Jobs), Data and Storage; `context/code-standards.md` Next.js, Data and Storage; `AGENTS.md`.

## C. Context and Dependencies

- **Prerequisites:** AI-001 complete and verified (Trigger.dev configured).
- **Contract introduced:** The `generateGraph` task and the `SystemaGraphSchema` Zod schema. The client (AI-003) will consume the task's output.
- **Contract consumed:** `prisma` from `@/lib/db` (for reading the current project state), `SystemaNodeData` from `@/components/editor/canvas/shapes` (for type reference).
- **Approved decisions:**
  - **AI Provider:** Gemini is primary (`gemini-3.5-flash` or latest free-tier model), Groq is fallback (`gpt-oss-120b` or `qwen/qwen3.8-27b`). Both have free tiers [citation:2][citation:3].
  - **Structured Output:** The AI must return a JSON object with `nodes` and `edges` arrays. Use Gemini's `responseSchema` or Groq's `response_format: { type: "json_object" }` to enforce this [citation:4][citation:5].
  - **Fallback Logic:** If Gemini fails (rate limit, timeout, invalid JSON), retry once with Groq. If both fail, throw an error.
  - **Prisma Pooling:** The task must use a Prisma client with `max: 1` connection pool size to avoid exhausting Neon's connection limit [citation:1][citation:8]. Since the Next.js app already has its own `prisma` singleton, create a separate client for Trigger.dev tasks in `lib/ai/db.ts` or inside the task file.
  - **No Blob Persistence Here:** This unit focuses on _generating_ the graph. Saving it to Vercel Blob and linking it to a `CanvasSnapshot` is PERSIST-001's responsibility. The task returns the JSON directly.

## D. Implementation Requirements

### 1. `lib/ai/client.ts`

Create a file that exports two functions: `generateWithGemini` and `generateWithGroq`. Both accept a `prompt: string` and return a parsed JSON object.

- **Gemini:** Use `@google/generative-ai`. Configure it with `gemini-3.5-flash` (or a free-tier model from the docs). Pass the `SystemaGraphSchema` as a `responseSchema` if supported by the SDK version; otherwise, instruct the model in the system prompt to return only JSON.
- **Groq:** Use `groq-sdk`. Configure it with `gpt-oss-120b`. Set `response_format: { type: "json_object" }` and include a system prompt instructing the model to return valid JSON only.
- **Fallback Wrapper:** Export an `async function generateGraph(prompt: string)` that tries Gemini first. On any error (rate limit, network, invalid JSON), it logs the failure and retries with Groq. If both fail, throw an error with the aggregated messages.

### 2. `lib/ai/schema.ts`

Define a Zod schema that matches the expected graph output. This schema is used for runtime validation of the AI's response.

START OF schema.ts snippet

    import { z } from "zod";

    export const SystemaNodeSchema = z.object({
      id: z.string(),
      type: z.enum(["rectangle", "diamond", "circle", "pill", "cylinder", "hexagon"]),
      position: z.object({ x: z.number(), y: z.number() }),
      data: z.object({
        name: z.string(),
        description: z.string().optional().default(""),
        color: z.enum(["slate", "blue", "violet", "green", "amber", "rose"]).default("slate"),
      }),
    });

    export const SystemaEdgeSchema = z.object({
      id: z.string(),
      source: z.string(),
      target: z.string(),
      data: z.object({
        name: z.string().optional().default(""),
        description: z.string().optional().default(""),
      }).optional().default({}),
    });

    export const SystemaGraphSchema = z.object({
      nodes: z.array(SystemaNodeSchema),
      edges: z.array(SystemaEdgeSchema),
    });

    export type SystemaGraph = z.infer<typeof SystemaGraphSchema>;

END OF schema.ts snippet

### 3. `trigger/generate-graph.ts`

Create the Trigger.dev task.

START OF generate-graph.ts snippet

    import { task } from "@trigger.dev/sdk/v3";
    import { PrismaPg } from "@prisma/adapter-pg";
    import { PrismaClient } from "@prisma/client";
    import { generateGraph as aiGenerate } from "@/lib/ai/client";
    import { SystemaGraphSchema } from "@/lib/ai/schema";

    // Separate Prisma client for Trigger.dev to limit pooling
    const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL_UNPOOLED || process.env.DATABASE_URL, max: 1 });
    const prisma = new PrismaClient({ adapter });

    export const generateGraphTask = task({
      id: "generate-graph",
      run: async (payload: { projectId: string; prompt: string; currentGraph?: any }) => {
        console.log(`Generating graph for project ${payload.projectId} with prompt: ${payload.prompt}`);

        // 1. Build the system prompt with the current graph context
        const systemPrompt = `You are a system architecture assistant. The user wants to generate or modify a system design based on this prompt: "${payload.prompt}".
        ${payload.currentGraph ? `Here is the current graph state: ${JSON.stringify(payload.currentGraph)}. Extend or modify it as requested.` : "Create a new system architecture from scratch."}
        Return ONLY a JSON object with "nodes" and "edges" arrays. Do not include markdown formatting or explanations.`;

        try {
          // 2. Call the AI with fallback logic
          const rawGraph = await aiGenerate(systemPrompt);

          // 3. Validate the AI response
          const parsed = SystemaGraphSchema.parse(rawGraph);
          console.log(`Generated ${parsed.nodes.length} nodes and ${parsed.edges.length} edges.`);

          // 4. Return the validated graph
          return { success: true, graph: parsed };
        } catch (error) {
          console.error("Graph generation failed:", error);
          throw error;
        } finally {
          await prisma.$disconnect();
        }
      },
    });

END OF generate-graph.ts snippet
