# AI-002 — Graph Generation Task

## A. Identity and Objective

- **Feature ID:** AI-002
- **Title:** Graph Generation Task
- **Primary objective:** Create a Trigger.dev background task that accepts a plain-English prompt and the current canvas state, calls an AI provider (Gemini primary, Groq fallback), and returns a structured JSON graph (nodes and edges) that the client can apply to the canvas.
- **Expected outcome:** The task validates its payload, calls Gemini, falls back to Groq on failure, validates the AI response against the `SystemaNodeData` schema, and writes the generated graph to Postgres/Vercel Blob (or returns it directly). The task runs successfully in the Trigger.dev dashboard.
- **References:** `planning/feature-map.md` AI-002; `context/architecture.md` Stack (AI, Background Jobs), Data and Storage; `context/code-standards.md` Next.js, Data and Storage; `AGENTS.md`.

## C. Context and Dependencies

- **Prerequisites:** AI-001 complete and verified (Trigger.dev configured).
- **Contract introduced:** The `generateGraph` task and the `SystemaGraphSchema` Zod schema. The client (AI-003) will consume the task's output.
- **Contract consumed:** `prisma` from `@/lib/db` (for reading the current project state), `SystemaNodeData` from `@/components/editor/canvas/shapes` (for type reference).
- **Approved decisions:**
  - **AI Provider:** Gemini is primary (`gemini-3.5-flash` or latest free-tier model), Groq is fallback (`openai/gpt-oss-120b` or `qwen/qwen3.8-27b`). Both have free tiers [citation:2][citation:3].
  - **Structured Output:** The AI must return a JSON object with `nodes` and `edges` arrays. Use Gemini's `responseSchema` or Groq's `response_format: { type: "json_object" }` to enforce this [citation:4][citation:5].
  - **Fallback Logic:** If Gemini fails (rate limit, timeout, invalid JSON), retry once with Groq. If both fail, throw an error.
  - **Generation contract:** Return additions only. Use the supplied current graph as context, but do not repeat or modify its nodes or edges. New edges may connect to generated nodes or nodes in the supplied current graph only.
  - **Prisma Pooling:** The task must use a Prisma client with `max: 1` connection pool size to avoid exhausting Neon's connection limit [citation:1][citation:8]. Since the Next.js app already has its own `prisma` singleton, create a separate client for Trigger.dev tasks in `lib/ai/db.ts` or inside the task file.
  - **No Blob Persistence Here:** This unit focuses on _generating_ the graph. Saving it to Vercel Blob and linking it to a `CanvasSnapshot` is PERSIST-001's responsibility. The task returns the JSON directly.

## D. Implementation Requirements

### 1. `lib/ai/client.ts`

Create a file that exports two functions: `generateWithGemini` and `generateWithGroq`. Both accept a `prompt: string` and return a parsed JSON object.

- **Gemini:** Use `@google/generative-ai`. Configure it with `gemini-3.5-flash` (or a free-tier model from the docs). Pass a provider-compatible structural response schema derived from `SystemaGraphSchema` if supported by the SDK version; always run the full context-aware Zod schema, including its refinements, on the response before the attempt succeeds. Otherwise, instruct the model in the system prompt to return only JSON.
- **Groq:** Use `groq-sdk`. Configure it with the supported model ID `openai/gpt-oss-120b`. Preserve `response_format: { type: "json_object" }` and include the shared system prompt instructing the model to return valid JSON only.
- **Fallback Wrapper:** Export an `async function generateGraph(prompt: string, permittedExistingNodeIds: ReadonlySet<string>)` that tries Gemini first. Each attempt must parse its provider response with `SystemaGraphSchema(permittedExistingNodeIds)` before that attempt succeeds. On any provider or schema-validation error (rate limit, network, invalid JSON, or invalid graph), log the failure and retry with Groq using the same prompt and schema guidance. If both fail, throw an error with the aggregated messages.
- Both provider requests receive the same system prompt. It must specify the exact node fields (`id`, `type`, `position: { x, y }`, and `data: { name, description, color }`), the allowed node types (`rectangle`, `diamond`, `circle`, `pill`, `cylinder`, `hexagon`), the allowed colors (`slate`, `blue`, `violet`, `green`, `amber`, `rose`), and the edge fields (`id`, `source`, `target`, and `data: { name, description }`). Require JSON only, with no Markdown or explanation. For an existing graph, identify its nodes and IDs as context, instruct the model to return only new nodes and edges, and permit edge endpoints to refer only to generated node IDs or IDs in that supplied graph.

### 2. `lib/ai/schema.ts`

Define a Zod schema that matches the expected graph output. This schema is used for runtime validation of the AI's response.

START OF schema.ts snippet

    import { z } from "zod";

    export const SystemaNodeSchema = z.object({
      id: z.string(),
      type: z.enum(["rectangle", "diamond", "circle", "pill", "cylinder", "hexagon"]),
      position: z.object({ x: z.number(), y: z.number() }),
      data: z.object({
        name: z.string(),
        description: z.string().default(""),
        color: z.enum(["slate", "blue", "violet", "green", "amber", "rose"]).default("slate"),
      }),
    });

    export const SystemaEdgeSchema = z.object({
      id: z.string(),
      source: z.string(),
      target: z.string(),
      data: z.object({
        name: z.string().default(""),
        description: z.string().default(""),
      }).default({ name: "", description: "" }),
    });

    const SystemaGraphBaseSchema = z.object({
      nodes: z.array(SystemaNodeSchema),
      edges: z.array(SystemaEdgeSchema),
    });

    export const SystemaGraphSchema = (permittedExistingNodeIds: ReadonlySet<string>) =>
      SystemaGraphBaseSchema.superRefine((graph, ctx) => {
        const generatedNodeIds = new Set<string>();
        graph.nodes.forEach((node, index) => {
          if (generatedNodeIds.has(node.id)) {
            ctx.addIssue({ code: "custom", path: ["nodes", index, "id"], message: "Duplicate node ID" });
          }
          generatedNodeIds.add(node.id);
        });

        const generatedEdgeIds = new Set<string>();
        graph.edges.forEach((edge, index) => {
          if (generatedEdgeIds.has(edge.id)) {
            ctx.addIssue({ code: "custom", path: ["edges", index, "id"], message: "Duplicate edge ID" });
          }
          generatedEdgeIds.add(edge.id);
          for (const endpoint of ["source", "target"] as const) {
            const nodeId = edge[endpoint];
            if (!generatedNodeIds.has(nodeId) && !permittedExistingNodeIds.has(nodeId)) {
              ctx.addIssue({ code: "custom", path: ["edges", index, endpoint], message: "Unknown edge endpoint" });
            }
          }
        });
      });

    export type SystemaGraph = z.infer<typeof SystemaGraphBaseSchema>;

END OF schema.ts snippet

### 3. `trigger/generate-graph.ts`

Create the Trigger.dev task.

START OF generate-graph.ts snippet

    import { task } from "@trigger.dev/sdk/v3";
    import { PrismaPg } from "@prisma/adapter-pg";
    import { PrismaClient } from "@prisma/client";
    import { generateGraph as aiGenerate } from "@/lib/ai/client";
    import type { SystemaGraph } from "@/lib/ai/schema";

    // Separate Prisma client for Trigger.dev to limit pooling
    const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL_UNPOOLED || process.env.DATABASE_URL, max: 1 });
    const prisma = new PrismaClient({ adapter });

    export const generateGraphTask = task({
      id: "generate-graph",
      run: async (payload: { projectId: string; prompt: string; currentGraph?: SystemaGraph }) => {
        console.log(`Generating graph for project ${payload.projectId} with prompt: ${payload.prompt}`);

        // 1. Build the shared system prompt with the current graph context
        const systemPrompt = `You are a system architecture assistant. Generate only new additions for this request: "${payload.prompt}".
        ${payload.currentGraph ? `Current graph context (do not repeat or modify these nodes or edges): ${JSON.stringify(payload.currentGraph)}. New edges may connect to nodes whose IDs appear in this graph.` : "There is no existing graph."}
        Return only a JSON object with "nodes" and "edges" arrays. Each node must have id (string), type (one of rectangle, diamond, circle, pill, cylinder, hexagon), position ({ x: number, y: number }), and data ({ name: string, description: string, color: one of slate, blue, violet, green, amber, rose }). Each edge must have id (string), source (node ID), target (node ID), and data ({ name: string, description: string }). Edge endpoints must refer to a generated node or a node in the supplied current graph. Return valid JSON only, with no Markdown or explanations.`;

        try {
          // 2. Each provider attempt validates against generated and explicitly permitted existing node IDs.
          const permittedExistingNodeIds = new Set(payload.currentGraph?.nodes.map((node) => node.id) ?? []);
          const graph = await aiGenerate(systemPrompt, permittedExistingNodeIds);
          console.log(`Generated ${graph.nodes.length} nodes and ${graph.edges.length} edges.`);

          // 3. Return only the validated additions.
          return { success: true, graph };
        } catch (error) {
          console.error("Graph generation failed:", error);
          throw error;
        } finally {
          await prisma.$disconnect();
        }
      },
    });

END OF generate-graph.ts snippet
