## C. Context and Dependencies

- **Prerequisites:** AI-002 complete and verified (the task exists and works).
- **Contract introduced:** The `/api/ai/generate` endpoint and the functional Prompt tab.
- **Contract consumed:** `generateGraphTask`, `SystemaGraphSchema`, Liveblocks `useMutation`.
- **Approved decisions:**
  - **Invariant #2:** The AI task runs in Trigger.dev, never inline in the Next.js route. The route only triggers the task and returns the run ID.
  - **Applying the graph:** The client must not replace the canvas. The request sends the current graph to the generation task, which returns additions only; append those additions to Liveblocks Storage without duplicating existing nodes or edges.
  - **Run status authorization:** Return the Trigger.dev handle's run-scoped `publicAccessToken` with the run ID and use it only to observe that run. Verify the installed SDK documents this token as run-scoped before exposing it. Never return `TRIGGER_SECRET_KEY` or another project-wide credential. If the installed SDK does not provide a safe run-scoped token, use an authenticated status route that verifies both project access and the run's association with that project; never poll a run using only an unauthenticated run ID.
  - **Status handling:** The UI must show distinct states: Idle, Generating (loading), Success, and Error.
  - **Liveblocks Mutation:** Since the canvas is wrapped in `LiveblocksRoom`, the AI Sidebar (rendered inside the shell) can use `useMutation` to push new nodes to the `flow` storage.

## D. Implementation Requirements

### 1. Create `app/api/ai/generate/route.ts`

Create a Route Handler that validates the request and triggers the task.

START OF route.ts snippet

    import { NextResponse } from "next/server";
    import { auth } from "@clerk/nextjs/server";
    import { tasks } from "@trigger.dev/sdk/v3";
    import { generateGraphTask } from "@/trigger/generate-graph";
    import { requireProjectAccess } from "@/lib/server/auth";

    export async function POST(req: Request) {
      try {
        const { userId } = await auth();
        if (!userId) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

        const body = await req.json();
        const { projectId, prompt, currentGraph } = body;

        const request = GenerateGraphRequestSchema.safeParse({ projectId, prompt, currentGraph });
        if (!request.success) {
          return NextResponse.json({ error: "Invalid generation request" }, { status: 400 });
        }

        // Enforce access (Invariant #1)
        await requireProjectAccess(request.data.projectId);

        // Trigger the task (Invariant #2)
        const handle = await tasks.trigger<typeof generateGraphTask>("generate-graph", {
          ...request.data,
        });

        return NextResponse.json({
          success: true,
          runId: handle.id,
          publicAccessToken: handle.publicAccessToken,
        });
      } catch (error: any) {
        console.error("AI Route Error:", error);
        return NextResponse.json({ error: error.message || "Internal error" }, { status: 500 });
      }
    }

END OF route.ts snippet

`GenerateGraphRequestSchema` validates `projectId`, `prompt`, and the complete `currentGraph` before triggering the task. Validate graph node/edge IDs and endpoint references with Zod; do not trust a client-supplied graph merely because project access succeeded.

### 2. Update `components/editor/ai-sidebar.tsx`

The right sidebar currently has a placeholder for the "Prompt" tab. Replace it with a functional component:

- **State:** `prompt` (string), `status` ('idle' | 'generating' | 'success' | 'error'), `errorMessage` (string).
- **Liveblocks Mutation:**
  START OF mutation snippet
  import { useMutation } from "@liveblocks/react";
  const applyGraph = useMutation(({ storage }, newNodes, newEdges) => {
  const flow = storage.get("flow");
  const nodes = flow.get("nodes");
  const edges = flow.get("edges");
  // Append new nodes and edges
  newNodes.forEach(n => nodes.push(n));
  newEdges.forEach(e => edges.push(e));
  }, []);
  END OF mutation snippet

- **Submit Handler:**
  1. Set status to 'generating'.
  2. Read the current graph from Liveblocks Storage and send `fetch('/api/ai/generate', { method: 'POST', body: JSON.stringify({ projectId, prompt, currentGraph }) })`.
  3. If the fetch fails, set status to 'error'.
  4. If the fetch succeeds, use the installed Trigger.dev realtime hook/API with both `runId` and the run-scoped `publicAccessToken` to observe that run. Verify the installed SDK supports this exact contract. Do not use a client-side Trigger.dev API key or poll a run by ID without authorization.
  5. When the run succeeds and returns `{ success: true, graph }`, remap IDs before calling `applyGraph(graph.nodes, graph.edges)`: compare generated node IDs against current node IDs and other generated node IDs, and generated edge IDs against current edge IDs and other generated edge IDs; replace each collision with a fresh UUID. Maintain a mapping from every original generated node ID to its final ID, then update generated edge `source` and `target` references through that mapping. Append the resulting additions only.
  6. Set status to 'success'.

- **UI Layout:**
  - A `<Textarea>` for the prompt.
  - A `<Button>` "Generate" (disabled when loading or prompt is empty).
  - A status area: show a loading spinner/text when generating, a green success message, or a red error message.
  - Place this inside the `TabsContent` for the "Prompt" tab.
