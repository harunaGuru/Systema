# UI-003 — Geist Fonts

## A. Identity and Objective

- **Feature ID:** UI-003
- **Title:** Geist Fonts
- **Primary objective:** Load Geist Sans and Geist Mono via `next/font` so the approved `--font-sans` and `--font-mono` tokens in `globals.css` resolve to real fonts.
- **Expected outcome:** The root layout sets `--font-geist-sans` and `--font-geist-mono` on `<html>`; body text renders in Geist Sans; a mono sample renders in Geist Mono.
- **References:** `planning/feature-map.md` UI-003; `context/ui-context.md` Typography; `AGENTS.md`.

## B. Execution Contract

The agent must do all of the following without asking the user for confirmation, in this order:

1. Read `AGENTS.md`, `context/ui-context.md` (Typography section), and `app/layout.tsx`.
2. Confirm UI-002 is in place: `components.json` exists, `app/globals.css` contains `--color-bg-base`, `--font-sans`, and `--font-mono`.
3. Install the Geist package: run `npm install geist`.
4. Edit `app/layout.tsx` to import `GeistSans` and `GeistMono` from `geist/font/sans` and `geist/font/mono`, and apply both `.variable` classes to `<html>` alongside any existing className.
5. Replace `app/page.tsx` with the font sample described in D.3.
6. Run the **Checks** block in Section I top to bottom.
7. Fix any in-scope failure and re-run the failing check.
8. Report PASS or FAIL per Section J. On PASS, state that the agent has stopped and is awaiting the next feature. On FAIL, state the exact blocker and stop.

Do not install any other package. Do not modify `app/globals.css` (the `--font-sans` and `--font-mono` tokens already reference `--font-geist-sans` and `--font-geist-mono`; this unit supplies those variables). Do not modify `components/ui/*`.

## C. Context and Dependencies

- **Prerequisites:** UI-001 (scaffold) and UI-002 (tokens and primitives) complete and verified.
- **Contract consumed:** `--font-sans` and `--font-mono` in `app/globals.css` already fall back to `var(--font-geist-sans)` and `var(--font-geist-mono)`. This unit defines those two variables.
- **Approved decision:** Geist Sans for UI text, Geist Mono for code and canvas labels (`ui-context.md` Typography).

## D. Implementation Requirements

### 1. Install the Geist package

Run `npm install geist`. The `geist` package ships the font files and the `next/font`-compatible exports. It is the recommended way to use Geist with Next.js; `next/font/google` is an alternative but may strip OpenType features.

### 2. Wire the fonts into the root layout

`app/layout.tsx` must import both fonts and apply their variable classes to `<html>`:

- Import `GeistSans` from `geist/font/sans`.
- Import `GeistMono` from `geist/font/mono`.
- The `<html>` element must have `className` containing both `${GeistSans.variable}` and `${GeistMono.variable}`.

If the existing `<html>` has a `className`, merge rather than replace. If `app/layout.tsx` already imports a font, remove that import and replace it with the Geist imports; do not keep two font systems.

### 3. Replace `app/page.tsx` with a font sample

Render a page that proves both fonts resolve:

- A `<main>` with classes `min-h-screen bg-bg-base text-text-primary p-8 space-y-6`.
- An `<h1>` using `font-sans text-2xl` with text "Systema fonts".
- A paragraph using `font-sans text-text-muted` with text "This paragraph renders in Geist Sans via `--font-sans`."
- A `<pre>` or `<code>` block using `font-mono text-sm bg-bg-surface p-4 rounded-md border border-border-default` containing the text `const systema = "Geist Mono via --font-mono";`.
- A heading "Canvas label sample" using `font-mono text-xs text-text-muted`.
- A `<div>` using the `mono-label` utility class (defined in `globals.css`) containing the text "API Gateway".

Every sample must be readable against the dark background.
