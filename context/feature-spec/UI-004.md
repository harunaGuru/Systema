# UI-004 — Editor Chrome (Navbar + Left Sidebar Shell)

## A. Identity and Objective

- **Feature ID:** UI-004
- **Title:** Editor Chrome (Navbar + Left Sidebar Shell)
- **Primary objective:** Build the reusable TopNavbar and floating left sidebar shell that every editor screen will use, with mock content and no backend.
- **Expected outcome:** A working navbar with sidebar toggle, and a floating left sidebar with tabs and a New Project button. Both render on a sample page, both use only Systema tokens, and the sidebar slides in from the left with reduced-motion support.
- **References:** `planning/feature-map.md` UI-004; `context/ui-context.md` Layout Patterns, Icons, Interaction States; `context/code-standards.md` Styling, Next.js; `AGENTS.md`.

## B. Execution Contract

The agent must do all of the following without asking the user for confirmation, in this order:

1. Read `AGENTS.md`, `context/ui-context.md` (Layout Patterns, Icons, Interaction States), `context/code-standards.md` (Styling, Next.js).
2. Confirm UI-003 is in place: `geist` is installed, `app/layout.tsx` applies both font variables, `app/globals.css` contains `--color-bg-surface` and `--radius-md`.
3. Install Lucide: run `npm install lucide-react`.
4. Create `components/editor/editor-navbar.tsx` per D.2.
5. Create `components/editor/project-sidebar.tsx` per D.3.
6. Create `components/editor/editor-shell.tsx` per D.4.
7. Replace `app/page.tsx` with a page that renders `<EditorShell>` per D.5.
8. Run the **Checks** block in Section I top to bottom.
9. Fix any in-scope failure and re-run the failing check.

Do not install any other package. Do not modify `app/globals.css`, `app/layout.tsx`, or `components/ui/*`.

## C. Context and Dependencies

- **Prerequisites:** UI-001, UI-002, UI-003 complete and verified.
- **Approved decisions (from `ui-context.md`):**
  - TopNavbar has three sections: (1) sidebar toggle wired to hooks, (2) AI job status indicator + recovery snapshot restore icon, (3) Clerk user avatar with logout menu.
  - This unit builds section 1 and placeholders for 2 and 3. Section 2's real content and section 3's Clerk integration belong to AUTH-001 and later units. Leave both as disabled icon placeholders with `title` attributes.
  - Left sidebar: header, then two tabs — **My Projects** and **Shared** — listing projects, with a **New Project** button below.
  - Floating treatment: use the `floating-panel` utility defined in `globals.css`.
  - Sidebar slides from the left, ~200ms ease-out, respects `prefers-reduced-motion`. When closed, it is fully removed from the screen (not just hidden) so the canvas gets the full viewport.
  - Icons: Lucide only. `h-4 w-4` inline, `h-5 w-5` buttons. Icons inherit `currentColor`.

## D. Implementation Requirements

### 1. Package

Run `npm install lucide-react`. No other packages.

### 2. `components/editor/editor-navbar.tsx`

A client component (`"use client"`) because it receives callbacks.

Props:

- `isSidebarOpen: boolean`
- `onToggleSidebar: () => void`

Structure:

- `<header>` with classes `h-14 flex items-center justify-between px-4 border-b border-border-default bg-bg-base/80 backdrop-blur-md`.
- Left section: a `<button>` calling `onToggleSidebar`, `aria-label` "Toggle sidebar", containing `PanelLeftClose` when open and `PanelLeftOpen` when closed, `h-5 w-5`.
- Center section: empty `<div>` (reserved for future content).
- Right section: two disabled placeholder icon buttons and one placeholder avatar:
  - `<button>` with `Sparkles` icon, `aria-label` "AI status", `title` "AI status (available after AI-003)", `disabled`.
  - `<button>` with `History` icon, `aria-label` "Recovery snapshots", `title` "Recovery snapshots (available after PERSIST-002)", `disabled`.
  - `<div>` circular placeholder `h-8 w-8 rounded-full bg-bg-elevated` with `aria-label` "User menu (available after AUTH-001)", `title` "User menu (available after AUTH-001)".
- All buttons use `p-2 rounded-md hover:bg-bg-elevated text-text-primary` and `focus-visible:outline-2 focus-visible:outline-accent-primary focus-visible:outline-offset-2`.

Do not add Clerk, Trigger.dev, or Liveblocks imports. Do not wire the placeholder buttons to any handler.

### 3. `components/editor/project-sidebar.tsx`

A client component.

Props:

- `isOpen: boolean`
- `onClose: () => void`

Structure:

- Rendered only when `isOpen` is true. When false, return `null` (fully removed from the DOM).
- Outer `<aside>` with `fixed left-0 top-14 bottom-0 w-72 z-40 floating-panel rounded-md m-2 animate-slide-in-left`.
- Header row: `<h2>` "Projects" in `text-sm font-medium text-text-primary`, plus an icon button with `X` icon calling `onClose`, `aria-label` "Close sidebar".
- Tabs: shadcn `<Tabs defaultValue="owner">` with two `<TabsTrigger>` values `owner` and `shared`, labels "My Projects" and "Shared". Both `<TabsContent>` render an empty state: `flex flex-col items-center justify-center py-8 text-sm text-text-muted` with text "No projects yet."
- Footer: full-width shadcn `<Button>` with `Plus` icon (`h-4 w-4 mr-2`) and text "New Project". `onClick` does nothing in this unit. Keep the button enabled so it is visible and focusable.

All colors come from tokens. No hardcoded hex.

### 4. `components/editor/editor-shell.tsx`

A client component that composes the chrome and manages sidebar state.

Structure:

- `"use client"`.
- `useState(false)` for `isSidebarOpen`.
- Outer `<div className="min-h-screen bg-bg-base text-text-primary">`.
- Inside it: `<EditorNavbar isSidebarOpen={isSidebarOpen} onToggleSidebar={() => setSidebarOpen(v => !v)} />`.
- Then `<ProjectSidebar isOpen={isSidebarOpen} onClose={() => setSidebarOpen(false)} />`.
- Then `<main className="pt-14 min-h-screen bg-bg-canvas">` containing a centered placeholder: `<div className="flex items-center justify-center h-[calc(100vh-3.5rem)]">` with text "Canvas placeholder" in `text-text-muted text-sm`.
- No `prefers-reduced-motion` media query in the component; the animation utility already handles it.

### 5. `app/page.tsx`

Replace with a page that imports `EditorShell` from `@/components/editor/editor-shell` and returns `<EditorShell />`. No metadata changes required.
